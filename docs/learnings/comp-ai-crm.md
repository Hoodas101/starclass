# 学习简报：Comp AI CRM（trycompai/crm）

> 来源：https://github.com/trycompai/crm （MIT License，单仓库）
> 学习时间：2026-09-07
> 目的：从 Comp AI CRM 提取值得学习的内容、功能与亮点，评估哪些可融入 edu-admin-system。

---

## 一、Comp AI CRM 是什么

开源、自托管的 **agent-first（智能体优先）CRM**。核心理念一句话：

> *"The agent is not a feature of the CRM; the CRM is where the agent keeps its notes."*
> 智能体不是 CRM 的一个功能；CRM 是智能体存放笔记的地方。

它把"与人打交道的脏活"（跟进、记录、推断、提醒）交给 agent，把"记录与核实"交给结构化数据。
对 edu-admin 的启示：**系统不该只是表单的堆叠，而应该成为机构日常运营的"工作台"。**

## 二、主要功能与亮点

### 2.1 产品级亮点

| 亮点 | 说明 |
| ---- | ---- |
| Agent-first 工作台 | 每条记录（联系人/公司/机会）都有 Agent 标签页 + 提问框，随时问"这个人最近怎么样" |
| 证据规则（evidence rule） | **"关于一个人的任何信息都不靠猜"**：强证据写入档案，弱证据变成"待人工确认的建议"，绝不伪造 |
| 邮箱同步（只读） | Gmail + Microsoft Graph 只读同步，agent 基于真实邮件上下文工作，无需额外授权 |
| 工作队列 | 用 `FOR UPDATE SKIP LOCKED` 租赁式派发，`dueAt` 驱动（非 cron），适合多进程消费且不重复执行 |
| 零 API Key 自托管 | 开箱即用，不依赖任何第三方 LLM 服务商配置即可跑通 |
| 单租户设计 | 刻意不做"组织"概念，降低 90% 权限复杂度 |
| URL 驱动列表状态 | 筛选/排序/分页全部进地址栏（nuqs），刷新、分享、返回键都可用 |
| UI 单一来源 | `packages/ui` 是唯一 UI 来源，调用方禁止覆盖样式 |
| 自带 18 个自有工具 | agent 调用链完全自定义，工具即产品的表达面 |
| 4 个 Markdown Skills | evidence.md / identity-matching.md / data-boundaries.md / writing-a-brief.md — 把 agent 行为规则写成文档，可审查可迭代 |

### 2.2 工程/架构亮点

- **技术栈**：Turborepo + Bun、Next.js App Router、shadcn/ui、NestJS + nestjs-trpc、Prisma + Postgres、Better Auth、Vercel AI Gateway。
- **无键盘快捷键、无 command palette、无暗色模式、无角色系统**（登录只靠 allow-list）——说明"没有这些"也是一种选择，功能要服务于核心场景。

## 三、迁移映射（Transfer Map）

### 3.1 已经在 edu-admin 中

| Comp AI 亮点 | edu-admin 对应物 |
| ------------ | ---------------- |
| 命令驱动体验 | ⌘K 快速切换（页面/成员/线索全局搜索） |
| 角色与权限 | 管理员/教练/销售/家长四角色 + 机构设置 |
| 自托管、零依赖第三方 | SQLite 单进程，同源部署，可选微信支付按需启用 |
| 异步任务队列 | 后端 job worker（续费提醒、自动缺勤、备份） |
| 单租户思路 | 一个机构 = 一个 SQLite 文件 |

### 3.2 高价值可融入（候选）

| # | 学习点 | 融入方案（edu-admin） | 收益 |
| - | ------ | --------------------- | ---- |
| 1 | **URL 驱动列表状态** | 把运营中心 `?tab=` 深链扩展到学员列表/排期/线索：筛选、分页、当前页签全部进 URL | 刷新/分享/返回可用，运营工作流更稳 |
| 2 | **每条记录的活动时间线** | 学员档案增加"动态时间线"：签到、续费、请假、补课、跟进、成长记录按时间聚合 | 一眼看清学员全貌，替代零散翻表 |
| 3 | **证据式记录** | 学员跟进/线索备注增加"确定性"分级（已核实/待确认），弱证据不写死档案 | 数据卫生，多人协作不互相污染 |
| 4 | **键盘优先扩展** | 在 ⌘K 基础上补常用快捷键（如 `g` 导航、`?` 快捷键面板） | 高频运营提速 |
| 5 | **agent 行为文档化** | 把"跟进话术/线索判定/缺勤判定"等业务规则写成 Markdown 规则卡，作为行为准则 | 规则可审查、可迭代，也为未来智能体预留接口 |

### 3.3 不迁移（明确排除）

- **研究型 agent + LLM 沙箱**：edu-admin 无云端依赖，不引入在线大模型调用。
- **邮箱同步（Gmail/Microsoft Graph）**：微信生态场景，邮件不是主沟通渠道。
- **SSO / IdP**：保持手机号 + 角色密码登录即可。
- **"无组织"设计**：edu-admin 面向机构内多角色，保留机构设置。

## 四、结论

Comp AI CRM 最值得学习的三件事：

1. **产品姿态**：系统是工作台而非表单集 — 把"看一个人/一件事的全貌"做成一条时间线。
2. **证据纪律**：记录区分"事实"与"推断"，弱证据降级为建议，不污染档案。
3. **工程克制**：URL 驱动状态、租赁式任务队列、单一 UI 来源 — 都是低成本高稳定性的地基功夫。

以上 #1（活动时间线）与 #2（证据式记录）与 edu-admin 的"成长记录/跟进/审计日志"能力天然契合，是优先级最高的融入方向。
